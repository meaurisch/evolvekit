# A2 Noise-Aware Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every place the search compares two numbers knows how noisy they are. One run-wide noise estimate (`work/noise.json`) feeds the behaviour-twin filter, the race, promotion, the hold-out veto, the improvement test, the elite rule and an optional re-evaluation of the best; the search's own samplers (LHS, TPE, the local step, parent selection, the archive's axes) are made to do what their names say. With no noise estimate (`σ̂ = 0`) every rule reads as it does today.

**Architecture:** A new leaf module `evolvekit/evaluate/noise.py` holds `Noise`: per stage key (`"<stage>"`, `"<stage>/private"`) and per KPI, each candidate's runs, mean and sample variance, pooled on read. The stage runners report per-KPI variances (`StageOutcome.kpi_var`, `vector_var`); `Cascade` observes every outcome, persists the file after each generation, and calibrates the estimate once from the seed when nothing replicates. Every rule reads the noise through five accessors (`sd`, `vector_sd`, `cv`, `vector_cv`, `score_sd`), each returning one side's noise — across-seed or paired by the stage's measured repeatability (Decision 1) — so the scale of each rule is one decision, not eight. A2.3c adds `evolvekit/search/screening.py` (the screening controller); A2.4b adds `reevaluations.jsonl` and one row loader that every view uses. A2.5 and A2.6 change `search/tuning.py`, `search/operators.py`, `search/archive.py`, `space.py` and the driver's planning. The verdict (`confirm.verdict_summary` / `decide` / `decision_of`) is not touched.

### Task A2.1a: A noise estimate the whole run shares — the estimate (statistics / search core)

**Files:**
- Create: `evolvekit/evaluate/noise.py`
- Modify: `evolvekit/evaluate/types.py`: `StageOutcome.kpi_var: dict[str, float]`, `StageOutcome.vector_var: dict[str, list[float]]`, `StageOutcome.seed_runs: dict[str, list[float]]` (per scalar KPI, the value of each seed's run, in seed order), `StageOutcome.seed_vectors: dict[str, list[list[float]]]` (per vector key, per seed, the vector), `StageOutcome.seed_list: tuple[int, ...]` (the seeds run) and `StageOutcome.instance_durations: list[float]` (per instance, the mean duration of its runs; A2.1b's calibration instance). All default empty.
- Modify: `evolvekit/evaluate/stages.py` `_combine`: fill them from the seeds' runs, vectors included (Decision 3: per vector key and element).
- Modify: `evolvekit/evaluate/fanout.py` `_combine`: fill them from the seeds within each instance.
- Modify: `evolvekit/evaluate/cascade.py`: `Cascade.noise`, `_note_noise`, the percent vector in `_normalise` (Decision 4), the save at the end of `evaluate_generation`.
- Modify: `evolvekit/evaluate/__init__.py`: export `Noise`.
- Test: `tests/test_noise.py` (new), `tests/test_seeds.py`, `tests/test_instance_fanout.py`

**Interfaces:**
- Produces, in `noise.py` (imports only `statistics`, `math`, `json`, `pathlib`, `dataclasses`, and `ledger._atomic_write`):
  - `NOISE_FILE = "noise.json"`; `CALIBRATION_ID = "(calibration)"`; `SEED_ID = "(seed)"` (the seed's own runs, the reference of every paired difference).
  - `class Noise`, constructed `Noise(path: Path | None = None)`; `Noise.load(path: Path) -> Noise` (missing or unreadable file → empty, never raises).
  - `observe(self, key: str, candidate_id: str, outcome: StageOutcome, *, is_seed: bool = False) -> None`. For every scalar KPI in `outcome.kpi_var` and every vector key in `outcome.vector_var` (per element), records an **across** entry `(runs, mean, var)` under `key`/`candidate_id`; for the seed (`is_seed`) also keeps its `seed_runs`/`seed_vectors` by seed under `SEED_ID`. For any other candidate with ≥ 2 seeds that the seed also ran, records a **paired** entry `(df, var_d)`: `d_s = x_s − seed_s` over the shared seeds (per KPI; per element for vectors), `var_d` its sample variance, `df = shared − 1`. An entry for the same id is **replaced** (an interrupted generation evaluated again must not count twice). Ignores outcomes that are not `ok`, `raced_out`, `abandoned`, or have fewer than 2 runs.
  - `repeatable(self, key: str) -> bool | None` and `set_repeatable(self, key: str, value: bool) -> None` (A2.1b measures it; `None` until then).
  - `sd(self, key: str, kpi: str) -> float`: one side's noise of one run of the stage-level value. Repeatable key: `sqrt(Σ df·var_d / Σ df / 2)` over paired entries (0.0 with none, i.e. at `seeds: 1`). Otherwise (not repeatable, or `None`): `sqrt(mean over across entries with runs ≥ 2 of var)`. `0.0` when there is none.
  - `sd_across(self, key: str, kpi: str) -> float`: always the across estimate (reported for engineers).
  - `vector_sd(self, key: str, vector_key: str, index: int) -> float | None`: the same choice, pooled **per vector key and per element** (`<kpi>_per_instance`, `<obj>_pct_of_baseline`, an evaluator's `bins_per_instance` alike); `None` when that element is unknown.
  - `cv(self, key: str, kpi: str) -> float` and `vector_cv(self, key: str, vector_key: str) -> float`: the relative one-side noise of one run on one element, `sqrt(mean over (entry, element) with |mean| > 0 of var_i / mean_i²)` (paired: `var_d,i / 2` over the seed's `mean_i²`); for a stage without instances `cv` uses the scalar entries. `0.0` when unknown.
  - `score_sd(self, key: str, score: ScoreConfig, seeds: int) -> float`: as Global Constraints say.
  - `known(self, key: str) -> bool`: any estimate (across or paired) with ≥ 1 df under `key`.
  - `save(self) -> None` (atomic; no-op without a path).
  - `to_status(self, key: str, score: ScoreConfig) -> dict` (used by A2.1b).
- Produces: `StageOutcome.kpi_var` — per scalar KPI, the sample variance (`statistics.variance`, n − 1) **of one run** of the stage-level value. Stage without instances: over its `seeds` runs. Per-instance stage: `fmean(vector_var[<kpi>_per_instance]) / M` (M instances; runs taken as independent across instances). `StageOutcome.vector_var` — per vector key, per element, the sample variance over seeds; on a per-instance stage `<kpi>_per_instance` holds each instance's variance over its seeds, **in raw units**. Both empty with one seed (`seed_runs`/`seed_vectors` are filled with one seed too: the seed's single run is the reference of a later paired difference).
- Produces: `work/noise.json`:

```json
{"schema": 1,
 "stages": {
   "full": {"repeatable": false,
            "kpis": {"cost": {"across": {"g001-c0002": {"runs": 3, "mean": 101.2, "var": 0.84}},
                              "paired": {"g001-c0002": {"df": 2, "var": 0.10}}}},
            "vectors": {"cost_per_instance": {"across": {"g001-c0002": [[100.1, 2.1, 3], [102.3, 1.9, 3]]},
                                              "paired": {"g001-c0002": [[2, 0.2], [2, 0.1]]}},
                        "cost_pct_of_baseline": {"across": {}, "paired": {}}},
            "seed": {"seeds": [0, 1, 2], "kpis": {"cost": [101.0, 100.4, 99.8]},
                     "vectors": {"cost_per_instance": [[100.0, 102.0], [99.5, 101.3], [99.9, 101.5]]}}},
   "full/private": {}}}
```

  An across element is `[mean_i, var_i, runs]`, a paired element `[df, var_d]`; `null` when that element is unknown (calibration, A2.1b). Mean and variance of an element are in the units of its vector (Decision 4).
- Produces: `Cascade.noise: Noise`, loaded from `work_dir / "noise.json"` in `__init__`, saved at the end of every `evaluate_generation`. `Cascade._note_noise(self, stage: StageConfig, candidate: Candidate, outcome: StageOutcome, *, private: bool) -> None` with key `f"{stage.id}/private" if private else stage.id` and `is_seed = candidate.operator == SEED_OPERATOR`, called after `_normalise` and before `_note_behaviour` for every command-stage outcome (public loop in `evaluate_generation`, and in `_run_private`).
- Units under `normalize: baseline` (`_normalise`, Decision 4): `vector_var[<obj>_per_instance]` **stays raw**; `vector_var[<obj>_pct_of_baseline][i] = (100 / ref_i)² · vector_var[<obj>_per_instance][i]` is added (and `seed_vectors[<obj>_pct_of_baseline]` the same way, so paired differences in percent exist); `kpi_var[obj] = fmean(pct variances) / M` (percent, the unit the score is in) and `kpi_var[f"{obj}_raw"] = fmean(raw variances) / M`.

import math
import random
import statistics

import pytest

from evolvekit.evaluate.noise import Noise
from evolvekit.evaluate.types import StageOutcome


def _out(kpis, *, kpi_var=None, vector_var=None, vectors=None, runs=3, ok=True, seed_runs=None, **extra):
    seed_runs = seed_runs or {}
    seeds = tuple(range(len(next(iter(seed_runs.values()))))) if seed_runs else tuple(range(runs))
    return StageOutcome(stage_id="full", ok=ok, kpis=kpis, kpi_var=kpi_var or {},
                        vector_var=vector_var or {}, vector_kpis=vectors or {}, runs=runs,
                        seed_runs=seed_runs, seed_list=seeds, **extra)


def _runs(values):
    """An outcome from per-seed values of `cost`, with its mean and variance."""
    return _out({"cost": statistics.fmean(values)}, kpi_var={"cost": statistics.variance(values)},
                seed_runs={"cost": list(values)}, runs=len(values))


def test_the_pooled_variance_is_the_mean_of_each_candidates_own(tmp_path):
    noise = Noise(tmp_path / "noise.json")
    noise.observe("full", "a", _out({"cost": 10.0}, kpi_var={"cost": 4.0}))
    noise.observe("full", "b", _out({"cost": 12.0}, kpi_var={"cost": 16.0}))
    noise.observe("full", "c", _out({"cost": 11.0}, runs=1))  # one run says nothing about noise
    assert noise.sd("full", "cost") == pytest.approx(math.sqrt(10.0))
    assert noise.sd("proxy", "cost") == 0.0 and noise.sd("full", "other") == 0.0


def test_observing_the_same_candidate_again_replaces_it(tmp_path):
    noise = Noise(tmp_path / "noise.json")
    noise.observe("full", "a", _out({"cost": 10.0}, kpi_var={"cost": 4.0}))
    noise.observe("full", "a", _out({"cost": 10.0}, kpi_var={"cost": 4.0}))
    noise.observe("full", "b", _out({"cost": 10.0}, kpi_var={"cost": 16.0}))
    assert noise.sd("full", "cost") == pytest.approx(math.sqrt(10.0)), "not (4 + 4 + 16) / 3"


def test_only_finished_outcomes_with_two_runs_enter_the_estimate(tmp_path):
    noise = Noise(tmp_path / "noise.json")
    noise.observe("full", "f", _out({}, kpi_var={"cost": 9.0}, ok=False))
    noise.observe("full", "r", _out({}, kpi_var={"cost": 9.0}, raced_out="behind"))
    noise.observe("full", "x", _out({}, kpi_var={"cost": 9.0}, abandoned=True))
    assert not noise.known("full") and noise.sd("full", "cost") == 0.0


def test_the_file_round_trips_and_a_broken_one_is_no_noise(tmp_path):
    path = tmp_path / "noise.json"
    noise = Noise(path)
    noise.observe("full", "a", _out({"cost": 10.0}, kpi_var={"cost": 4.0}))
    noise.save()
    assert Noise.load(path).sd("full", "cost") == pytest.approx(2.0)
    path.write_text("{not json", encoding="utf-8")
    assert Noise.load(path).sd("full", "cost") == 0.0


def test_the_score_sd_is_of_one_candidates_mean_over_its_runs():
    from evolvekit.config import ScoreConfig

    noise = Noise()
    noise.observe("full", "a", _out({"cost": 10.0, "late": 1.0}, kpi_var={"cost": 4.0, "late": 1.0}))
    score = ScoreConfig(objective="cost", direction="minimize", weights={"cost": 1.0, "late": 2.0})
    assert noise.score_sd("full", score, seeds=4) == pytest.approx(math.sqrt(4.0 + 4.0 * 1.0) / 2.0)


def test_the_relative_noise_skips_instances_at_zero():
    noise = Noise()
    noise.observe("full", "a", _out({"cost": 50.0}, kpi_var={"cost": 1.0},
                                    vectors={"cost_per_instance": [100.0, 0.0]},
                                    vector_var={"cost_per_instance": [4.0, 1.0]}))
    assert noise.cv("full", "cost") == pytest.approx(0.02), "sqrt(4 / 100**2); the instance at 0 is left out"
    assert noise.vector_sd("full", "cost_per_instance", 0) == pytest.approx(2.0)
    assert noise.vector_sd("full", "bins_per_instance", 0) is None


def test_vector_variances_are_pooled_per_key_and_element():
    """Decision 3: an evaluator's own vector on a stage without instances is pooled too."""
    noise = Noise()
    for cid, var in (("a", [1.0, 9.0]), ("b", [3.0, 7.0])):
        noise.observe("full", cid, _out({"bins": 5.0}, kpi_var={"bins": 0.0},
                                        vectors={"bins_per_instance": [5.0, 6.0]},
                                        vector_var={"bins_per_instance": var}))
    assert noise.vector_sd("full", "bins_per_instance", 0) == pytest.approx(math.sqrt(2.0))
    assert noise.vector_sd("full", "bins_per_instance", 1) == pytest.approx(math.sqrt(8.0))


def test_on_a_repeatable_stage_the_noise_is_the_paired_one_per_side():
    """Decision 1: value = f(program) + g(seed). Across seeds the spread is g's (large);
    the differences to the seed on the same seeds are nearly constant, so the paired
    noise is small. The accessor returns one side: var_d / 2."""
    noise = Noise()
    g = [0.0, 5.0, -5.0]
    noise.observe("full", "seed", _runs([100 + x for x in g]), is_seed=True)
    noise.observe("full", "a", _runs([99 + x + e for x, e in zip(g, (0.1, -0.1, 0.0))]))
    across = noise.sd("full", "cost")
    noise.set_repeatable("full", True)
    paired = noise.sd("full", "cost")
    assert across == pytest.approx(5.0, rel=0.02), "the seed's and a's spread over seeds, pooled"
    assert paired == pytest.approx(math.sqrt(statistics.variance([0.1, -0.1, 0.0]) / 2))
    assert noise.sd_across("full", "cost") == pytest.approx(across), "still reported"


def test_on_a_repeatable_stage_one_seed_has_no_noise():
    noise = Noise()
    noise.observe("full", "seed", _runs([100.0]), is_seed=True)
    noise.observe("full", "a", _out({"cost": 99.0}, runs=1, seed_runs={"cost": [99.0]}))
    noise.set_repeatable("full", True)
    assert noise.sd("full", "cost") == 0.0, "seeds: 1 on a repeatable evaluator is today's behaviour"


def test_repeatability_and_both_estimates_survive_a_resume(tmp_path):
    noise = Noise(tmp_path / "noise.json")
    noise.observe("full", "seed", _runs([100.0, 105.0, 95.0]), is_seed=True)
    noise.observe("full", "a", _runs([99.1, 103.9, 95.0]))
    noise.set_repeatable("full", True)
    noise.save()
    again = Noise.load(tmp_path / "noise.json")
    assert again.repeatable("full") is True
    assert again.sd("full", "cost") == pytest.approx(noise.sd("full", "cost"))
    assert again.sd_across("full", "cost") == pytest.approx(noise.sd_across("full", "cost"))


def test_the_pooled_variance_is_within_5_percent_of_the_truth_over_4000_candidates():
    """The estimator itself: 4000 candidates, 3 runs each, true sd 2. The pooled
    variance is unbiased; its SE is 4/sqrt(4000) = 0.063 (1.6 %), so 5 % is
    three SE away."""
    rng = random.Random(20261110)
    noise = Noise()
    for i in range(4000):
        mu = rng.uniform(50, 150)
        runs = [rng.gauss(mu, 2.0) for _ in range(3)]
        noise.observe("full", f"c{i}", _out({"cost": statistics.fmean(runs)},
                                            kpi_var={"cost": statistics.variance(runs)}))
    assert noise.sd("full", "cost") ** 2 == pytest.approx(4.0, rel=0.05)

## Decisions

Taken by the controller after the builder check (a fresh statistician read §5 and this plan
against the code and simulated the procedures the code runs; its report and simulation scripts
are kept with the build log's A2 entry). These override any task text above that disagrees.
Where a decision changes a test band, the measured rate is given with its SE.

1. **The noise a comparison means: paired when the evaluator is repeatable** (builder check's
   new question 1; supersedes the Global Constraints' unit paragraph where they differ). Every
   candidate runs on the same seeds, so for an evaluator that is deterministic given its seed
   (most `{seed}` solvers that are not bounded by wall-clock time) the across-seed spread is far
   larger than the noise in the *difference* of two candidates on matching seeds.
   - **Repeatability is measured once per run:** when the seed's final stage has a `{seed}`
     placeholder, the run evaluates the seed **once more on seed 0** on the calibration instance
     (decision 6). If every KPI of the repeat equals the first run to the 9-digit signature, the
     stage is `repeatable: true`; otherwise `false`. A stage without `{seed}` and with `seeds > 1`
     is `repeatable: false` (its runs are repeats of one command). A stage without `{seed}` and
     with `seeds: 1` has σ̂ = 0 and no extra run, as today. `noise.json` and `progress.noise`
     carry `repeatable` (null until measured).
   - **Not repeatable** (wall-clock solvers): the rules use the across-seed σ̂ exactly as the plan
     says (`sd`, `instance_sd`, `cv`, `score_sd`), and calibration (A2.1b) applies when nothing
     replicates; the repeat run is itself a replicate of seed 0 and enters the estimate.
   - **Repeatable:** the rules use the **paired** noise. For every candidate with ≥ 2 seeds, the
     per-seed differences to the seed's run at the same seed, `d_s = x_s − seed_s` (per KPI; per
     instance for vectors), give a sample variance `v_d`; pooled (df-weighted) over candidates.
     The accessors then return the noise **of one side of a comparison**: `sd² = v_d / 2` (so the
     difference of two candidates keeps sd `√2·sd`, and every rate derived for independent sides —
     the veto's 7.9 %, the twin's 84 %, the elite's 24 % — holds unchanged). At `seeds: 1` the
     paired noise is 0, which is today's behaviour, and the across-seed calibration is **not** used
     for the rules (it is still measured and reported, as `sd_across`, for engineers). The
     behaviour-twin rule on a repeatable stage stays the exact 9-digit hash (two programs that
     behave alike give equal numbers on the same seeds).
   - `noise.json` keeps both estimates per key and KPI (`across`, `paired`), so a resumed run
     reads the same numbers. Tests: a repeatable toy evaluator (value = f(program) + g(seed))
     shows a child 0.5 σ_across better than its parent is **not** a twin, **is** an improvement and
     **does** take the elite at `seeds: 1` and `seeds: 3`; a wall-clock toy (value = f(program) +
     fresh noise) reproduces the plan's rates.
2. **What a noise twin may reject** (new question 2; supersedes the plan's Q4 and A2.2's "twin
   of the first id it matches"). Against the whole index, "within the noise of anything" rejects
   nearly every child on a scalar stage (measured 97–100 % once the index holds 20–200
   candidates). On a stage that is not repeatable and has σ̂ > 0, a child is a twin only when an
   earlier candidate lies within the margin on every compared number **and that candidate's stage
   score is at least the child's** (it behaves like something already seen that did at least as
   well). It is "of" the best-scoring such candidate (ties: the first id). A child within the
   noise of everything but ahead of all its neighbours is evaluated. Tests add: a converged index
   of 50 near-equal entries and a child truly 1 sd above all of them is **not** a twin in ≥ 90 %
   of seeded trials (state the measured rate); an equal child is a twin in about half (state it).
3. **Compare one representation of each measure** (new question 3, top issue 3). The twin rule
   compares the evaluator's own numbers only: each reported scalar KPI, and each reported
   per-instance vector **in the stage's raw units**; derived numbers (`<obj>_pct_of_baseline`,
   `<obj>_raw`, a stage-level aggregate of a per-instance vector) are not compared. Every compared
   noisy number has a margin: per element from the pooled per-key, per-element variance (A2.1a
   pools `vector_var` per vector key and element, from `stages._combine` too); when an element's
   variance is unknown but the stage's `cv` is known, `cv·|value|`. `c_m` counts the compared
   numbers. The documented catch rate for true twins is "about 84 %".
4. **Units under `normalize: baseline`** (top issue 4). `vector_var[<obj>_per_instance]` stays raw;
   `vector_var[<obj>_pct_of_baseline]` is added, scaled by `(100/ref_i)²`; `kpi_var[obj]` (percent)
   and `kpi_var[<obj>_raw]` are derived from them. `noise.json`'s per-instance entries hold mean and
   variance in the same units. The test asserts the percent sd on the percent vector.
5. **The race also knows the case-to-case spread** (new question 4). At each look, with m ≥ 2
   compared instances, the margin is
   `max(margin_pct, 200·cv, 200·s_m/√m·√(1 − m/n))` percent, where `s_m` is the sample sd of the
   challenger-over-incumbent per-instance percent differences over the prefix (`m/n` the share of
   the n instances seen; the finite-population factor makes the last look's term 0). Measured
   without it: an equal-on-average candidate that trades cases (per-case effect sd 3 %) is raced
   out 30 %; the implementer measures the new rate (seeded, ≥ 4000 trials) and the test asserts
   < 10 %. The fixed looks are the one place where σ̂ = 0 is not exactly today (recorded); each look
   is read once per candidate (`_Board` keeps the last look read, so parallel workers and later
   seeds cannot trigger a second read at the same look). Docs: "under 1 % against a fresh
   incumbent, rising to about 5 % against the best of a long run".

## Open questions for the builder check

1. **The unit of σ̂ in each rule.** The design writes `σ̂_k` (A2.2), `σ̂_obj` (race, A2.4), `σ̂_stage` (promotion) and `σ̂/√seeds` (the veto) without saying whether each is one run's spread or one candidate's mean's, in raw units or percent of the seed, public or hold-out. Read literally, the epsilon `0.5·σ̂_obj` and the elite rule `+σ̂_obj` use one run's spread against fitnesses that are means over `seeds` runs — √seeds too strict at `seeds: 3`. *Proposed (in the plan):* one convention (Global Constraints): `Noise.sd` is one run of the stage-level KPI; `Noise.score_sd` is one candidate's stage score, `sqrt(Σ w_k² sd_k²)/√seeds`; the veto, promotion band, epsilon and elite rule read `score_sd`; the twin rule reads `sd` per KPI with its own `√(2/seeds)`; the race reads the per-instance relative `cv` because its comparison is a mean of ratios. With `normalize: baseline` all of them are in percent of the seed (A2.1a rescales the variance).
2. **The design's twin test is inverted.** "Two programs 0.3 % apart under 2 % noise are twins at 3 digits today and are not twins with the new rule": under 2 % noise the new margin is `2·2 %/√seeds` ≥ 1.2 %, so 0.3 % apart **are** twins under the new rule. The sentence holds for a small noise: with one run varying by 0.1 %, the margin is 0.2 %, 0.3 % apart are two candidates and 0.1 % apart one, while 3 significant digits merge both (100.0 and 100.3 both round to 100). *Proposed (in the plan):* the test uses 0.1 % noise (`test_a_small_noise_tells_apart_what_three_digits_could_not`), and a second test pins that a large noise merges what three digits told apart. The docs say both.
3. **The twin rule over many numbers is inert.** "For every signature KPI, per element for vectors, `|a − b| ≤ 2σ̂/√seeds`": each comparison catches a true twin with probability erf(1) = 84.3 %, so with ten instances all ten agree only 0.843¹⁰ = 18 % of the time, and the filter stops filtering as instances grow — the defect Q7 names, back by another route. *Proposed (in the plan):* the margin per number is `c_m·σ̂·√(2/seeds)` with `c_m = Φ⁻¹((1 + erf(1)^{1/m})/2)` over the m noisy numbers compared; `c_1 = √2`, so one number is the design's rule exactly, and a true twin is caught about 84 % of the time at any m (asserted for m = 10). Alternative: compare only the stage mean (one number) — simpler, but blind to a candidate that trades one instance for another.
4. **The twin rule throws away real gains smaller than the noise.** A difference of four noise sd (two margins) is still called a twin about 8 % of the time, and one of one margin about half the time; a twin is rejected, not merely flagged. This is what "indistinguishable" means, and under large noise it is coarser than 3 digits ever was. *Proposed:* keep it (the rule's purpose is not to pay twice for the dice), state the rates in the docs, and let the statistician review weigh whether a twin should be flagged instead of rejected on a stochastic stage.
5. **`evaluate.signature_digits_stochastic` goes.** The design says the rounding goes; the key is in the `init` template, two examples, `preflight` and the manual. *Proposed (in the plan):* a config error naming the noise rule (A0's precedent for `parent_top_k`), the examples and the template updated. Alternative: accept and ignore it with a warning.
6. **`search.novelty.behavioural: auto`.** It skips stochastic stages because "the filter is proven inert" there; with noise twins it no longer is. The harness compiles `off` for time-limited applications and `auto` otherwise. *Proposed (in the plan):* `auto` checks a stochastic stage once its objective has σ̂ > 0, and skips it while σ̂ is 0; the compile's choice is left as it is (changing a study's filter is outside A2).
7. **The race.** (a) "The incumbent's prefix is its seed-averaged per-instance values" is already true: `_note_incumbent` stores the means over all its seeds; the challenger's values are a one-seed prefix (`compared ≥ instances` ends the race after the first pass, so a race never sees a second seed). What S5 calls optimistic bias is selection: the incumbent is the best of many, so each of its values is lucky by about `E[max]·cv/√M`. (b) The design's margin `200·σ̂_obj/|incumbent mean|` is two per-run sds whatever the number of instances compared, so it is conservative: an equal candidate is raced out in about 0.25 % against a fresh incumbent and about 1.6 % against the best of eight, while a candidate 5 % behind at 2 % noise is caught about 88 % of the time. *Proposed (in the plan):* keep the design's formula with σ̂ read as the pooled per-run, per-instance relative sd (`Noise.cv`), the look schedule as written (`after`, then every ⌈n/4⌉, never at n), and assert the rates above. Alternative: `100·z·cv·√((1 + 1/S)/m)` per look (more power, needs its own look-adjusted z).
8. **The promotion band has no cap.** "Top k plus every candidate within 2σ̂ of the k-th": when the candidates are close, nearly all are promoted (eight equal candidates, k = 2: about seven a round) and the screen saves nothing. *Proposed (in the plan):* cap the promoted set at 2k by score. The cost: a candidate one noise sd better than the field is left out about 14 % of the time (estimate; today about 45 %), against about 3 % uncapped. The builder check measures both before the bound is fixed.
9. **The screening controller reads a restricted range.** ρ is computed over promoted candidates only — the top of each round by the screen — which pulls it toward 0 (`_screening_agreement` says so itself): a screen with ρ = 0.8 before selection shows about 0.58 among the top third, so "ρ < 0.2 → k + 1" fires in perhaps 20–40 % of runs whose screen is good (it costs time, not correctness), while "ρ < 0 twice → off" fires in about 1–3 % of them (asserted < 5 %). Also: (a) the design puts the controller in `harness/execute.py`, but a study's search runs inside `Driver.run()` with no per-round hook there; *proposed:* the engine runs it for a stage with `promote.adapt: true`, and the compile sets that on the study's screen stage, so engine configs are unchanged by default. (b) "Switched off": *proposed* the screen stage is skipped (its time saved), not run and ignored. (c) "The plan's about N rounds is recomputed when k changes": *proposed* no new code — `app/jobs.pace` already re-plans from the measured round durations, so a longer round shows in its next line; A4.1 makes re-planning general.
10. **Where the calibration runs.** The design has `preflight` and the study's preview run the seed twice more and "seed the estimate". Preflight works in a temporary directory, and the preview runs at a capped 10 s time limit (`PREVIEW_TIME_LIMIT_S`), whose noise is not the search's. *Proposed (in the plan):* the run calibrates itself, once, in the seed's generation (`Cascade._calibrate_noise`, the search's own time limit, two runs on the smallest instance); `preflight` runs the same two seeds and reports the noise line; the preview is unchanged (it would take three times as long for a number the run measures again). From one instance on a per-instance stage, the stage-level `sd` assumes the same relative noise on every instance and independence between them (formula in A2.1b); real replicates replace the calibration as soon as any candidate has them.
11. **Which σ̂ and which `seeds` the veto margin uses** (A0 decision 7). *Proposed (in the plan):* the hold-out's own estimate (`"<final>/private"`) when it exists (the seed's hold-out runs `seeds` times like every other), else the public final stage's `score_sd` rescaled by `|seed_private/seed_public|` (the same command on other cases: the relative noise transfers, the absolute one need not), else 0; `seeds` = the final stage's `seeds`; the margin is `2·score_sd`, i.e. the design's `2·σ̂/√seeds`. Because both sides are noisy, an equal candidate is kept out in P(Z < −√2) = 7.9 %; the docs' "about half" sentence becomes "about 8 %". Each row records the margin it was judged with (`holdout_margin`), so a resumed run and every view re-judge it with that margin, and a legacy row with the literal rule. With `score.levels` the margin is 0 (a level score is not linear in a KPI).
12. **The epsilon default changes deterministic runs.** `max(1e-9·|best|, 0.5·σ̂)` with σ̂ = 0 is `5.9e-9` on the quickstart (best ≈ −5.9) instead of today's `1e-6`, against "σ̂ = 0 degrades to today". *Proposed (in the plan):* `max(1e-6, 1e-9·|best|, 0.5·score_sd)`. Separately, `0.5·score_sd` lets an equal candidate read as an improvement over a single draw about 36 % of the time (asserted); against the best so far, a maximum, it is much rarer, which is the case that matters for patience. `_restore_stop_policy` replays the series with the noise as it is at resume, not as it was per generation: a resumed run's stagnation count can differ by a generation from the live one; *proposed:* accept and say so in the docs.
13. **The elite rule depends on insertion order.** `fitness > elite + σ̂` is not transitive: which candidate holds a cell depends on the order they arrived, and `_rebin` replays in id order (≈ arrival order). *Proposed:* accept (the order is the run's own and replays identically), pinned by `test_the_grid_rebuilds_from_run_records`.
14. **Re-evaluation seeds and pooling.** (a) The design's `1000 + k` collides with the final check's `CHECK_SEEDS = 1001 … 1012` from k = 1: the winner would be selected on the final check's own seeds. *Proposed (in the plan):* `2000 + k`, asserted above `max(CHECK_SEEDS)`, and `confirm`'s "seeds the search selected on" warning includes them. (b) "Its KPIs become the mean over all its runs": the score is not linear in the KPIs (penalties, levels), so *proposed* the pooled score is the run-weighted mean of the runs' scores, beside the pooled KPIs. (c) A lucky best that regresses leaves `StopPolicy.best` at the lucky value (no ratchet means it never moves down); *proposed* `StopPolicy.rebase` lowers it to the archive's new best without resetting patience.
15. **Re-evaluations must reach every view.** Rows are append-only, one per candidate; status, leaderboard, confirm and the harness read `runs.jsonl` directly. *Proposed (in the plan):* `reevaluations.jsonl` beside it and one loader `leaderboard.read_rows(run_dir)` (rows, pooled, veto replayed) that every ranking reader uses; the app's other readers of `runs.jsonl` (counts, lineage) need no pooled values.
16. **The LHS cube and the random stream.** One cube per generation could change how many numbers the run draws, and resume tests pin the stream (`tests/test_resume_random_stream.py`). *Proposed (in the plan):* each `param_lhs` child still draws its seed as today; the cube is built from the first one's. The untyped `# PARAMS` `param_lhs` has the same iid defect (Q3) and gets the same row hand-out.
17. **Ranks change little inside `propose_tpe`.** It only sorts by fitness to split, so ranks change nothing within one scale; what changes is the tiers (screened-out candidates enter on any scale, failed ones tie at the bottom). The design does not say where a **vetoed** candidate goes (it finished; its hold-out is worse than the seed's). *Proposed (in the plan):* in the raced-out tier, so TPE does not learn to propose where the hold-out falls.
18. **Bandwidth at the ends, and categorical priors.** "The larger of the gaps to the point's two nearest neighbours" is ambiguous for an end point (Hyperopt uses left and right neighbours). *Proposed (in the plan):* left and right neighbours with 0 and 1 as sentinels; clip [0.02, 0.5]. The prior component is specified for numbers only; *proposed* a bool or choice with a prior adds `4·weight` pseudo-counts on the prior value to its smoothed counts. The prior sits in both l and g; it still pulls proposals toward its value because the bad set is larger and dilutes it more (asserted in `test_a_prior_pulls_tpe_towards_its_value`).
19. **Which siblings are "taken".** *Proposed (in the plan):* every child of the generation proposed so far that has params (any operator), not only TPE children: a `param_local` child is as good a reason to look elsewhere.
20. **Quantile re-binning and parameter axes.** "Re-binned when the member count doubles" needs a start: *proposed* at 2, 4, 8 … members. Parameter axes need the space at `descriptor_value` time and a default resolved where `problem.parameters` and `search.archive` are both known; the "recommended order" exists only in the harness, so *proposed* the compile writes the descriptors explicitly and the engine default is the first two declared. These change MAP-Elites in the benchmark's own runs (they declare `problem.parameters`); bench after A2.6a if the final numbers move.
21. **Which children are "evaluated" for the pressure.** *Proposed (in the plan):* every child handed to the cascade, static-stage rejects and behavioural twins included (they cost an evaluation), but not novelty `no_op`/`duplicate` rejects or failed applies. `Archive.children` keeps counting every attempt for the views; the weight reads the new `pressure`.
22. **The 1/5 rule with few local children.** "≥ 1/5 of `param_local` children improved" per generation, with ×/÷1.2: with one local child a generation the step settles where half the steps succeed, with three where about 21 % do; the classic rule's equilibrium is 1/5 whatever the count. *Proposed:* build as designed (the clip keeps it bounded) and record the history in `perturb.json`; a window over the last ten local children is the alternative if the benchmark says so. "Improved on its parent" is `fitness > parent.fitness` with no noise margin; *proposed* keep (with noise it rewards luck a little; the clip bounds it).
23. **`noise.sd` in the status document.** *Proposed (in the plan):* `progress.noise = {stage, source, sd, cv, runs_per_candidate}` for the final stage; a new key, so the status schema stays 2.
24. **Where the docs are.** The design's README sections ("The novelty filters", "Stochastic evaluators", "Operators", "The hold-out penalty", "Adaptive breadth") live in `docs/reference.md` since #77, and "the README's operator section" is `docs/reference.md` "Operators". *Proposed:* edit them there; the README is unchanged unless its overview goes wrong.
25. **The calibration's runs and the daily cap.** *Proposed (in the plan):* the two calibration runs are not counted against `max_full_evals_per_day` (two runs, once, of the seed); re-evaluations are counted (they recur).
26. **The benchmark cannot see A2.1–A2.4.** Its solvers have neither `seeds: N` nor `{seed}` (the "mature" noise is a deterministic function of the configuration), so σ̂ = 0 and the noise rules are inert by construction; the acceptance measures A2.5 and A2.6 only. *Proposed:* say so in the PR and the build log; a noisy variant of the benchmark (a `{seed}` regime) is a follow-up, not part of A2, because the manual's numbers come from the script as it is.
