The builder check runs on this version. **Execution order:** the bake-off milestone first — Tasks 1, 2, 3, 4, 6, 7, 8 — then the mutation milestone — Tasks 5, 9 — then 10, 11, 12, 13. Task numbers are the task-level plan's.

**Goal:** a study may change a source tree: a candidate is a commit, the harness builds and benchmarks it, given branches can be compared with the verdict, a coding agent can be the mutation operator, and the result is a PR.

**Architecture:** the engine gains `problem.tree` beside `problem.skeleton` and `problem.parameters` (`config.ProblemConfig.tree: TreeConfig`). A candidate's `block` is a unified diff against a base commit (cumulative, never against the parent), materialised by the new `evolvekit/tree.py` as a detached git worktree at `<run>/work/trees/<id>` with one commit per candidate; `Cascade._materialise` returns the tree's folder (`{tree}`), the static stage on trees refuses files outside `open`, a new stage kind `builtin-build` runs `problem.tree.build` in it, and the `command` stages run with `{candidate}` = the tree folder and `{app}` = the program inside it. With `build`, the driver evaluates one candidate at a time. The harness declares `code:` (`manifest.Code`); the study declares `vary.code` (`study.CodeVary`); `compile_study` maps one to the other and `write_run` pins the base to a commit. A provider may `act` in a folder; the `agent_patch` operator turns the agent's edits into a diff. The bake-off is a run with zero rounds whose candidates are given refs, checked by `confirm` against the base. `study pr` turns the best candidate into a branch and a PR.

**Tech stack:** Python ≥ 3.11 standard library; `git` on `PATH` (this machine: git 2.50.1.windows.1; `gh` 2.88.1 is also on PATH), invoked by `subprocess` only; the existing providers. No new runtime dependency.

**Spec:** [docs/superpowers/specs/2026-11-07-agent-path-design.md](../specs/2026-11-07-agent-path-design.md), §2 and §5 (with §3.4 for the verdict document, §8 for the gate, §9 for testing).

## Global constraints

- One harness per application; `code:` is a section of it (spec §5.1).
- A candidate that touches a file outside `open` is refused at the static stage (spec §5.1, §5.4); the operators refuse it earlier as a format failure.
- Nothing is pushed and no PR is opened without `--yes` (spec §5.6).
- The verdict is the only claim; the PR body is `study report --markdown` (spec §2, §5.6). No command output, page or PR title says "better" outside the verdict's `line`.
- PyVRP is not a test subject (spec §5.7).
- `git` is required for code studies only; settings studies must still work without it: `evolvekit/tree.py` is imported only where a tree problem is handled, and no git process starts for a skeleton or parameters problem.
- Every git call goes through `tree._git` with `-c core.autocrlf=false -c core.quotepath=false -c core.longpaths=true` (this machine has `core.autocrlf=true`; a CRLF checkout would refuse LF diffs). Paths with spaces are argv items, never shell text.
- Windows first: worktrees under paths with spaces and drive letters; a tree held by a running solver is removed with retries, never by force-killing.
- The engineer's working tree and index are never touched: worktrees, temporary indexes and `refs/evolvekit/*` only.
- The app's words in every sentence for people (study, case, held-back case, starting point, measure, goal, rule, combination, round, final check; never KPI, seed, generation, instance, config, baseline); `--json` keeps the engine's keys (`candidates`, `commit`, `ref`).
- Branch `agent/3-code` from `agent/2-skills`; PR against `master`, stacked; merge commit. Never run `python tasks.py check` beside a demo study or the gate.

## Review focus

1. A diff that applies but leaves the tree unbuildable or the tests failing: `builtin-build` hard-rejects with `reject_reason` starting `build:` and the stderr tail as feedback, and the tree is removed (Task 3's `test_build_failure_is_a_hard_reject_with_feedback`, which also asserts the tree folder is gone after the run).
2. Two candidates whose diffs differ only in whitespace, in a comment, in context width or in `index` lines: the normalised diff makes them duplicates (Task 1's `test_normalise_diff_ignores_index_and_timestamps`; Task 2's `test_whitespace_only_diffs_are_duplicates`).
3. The repo has uncommitted changes when `vary.code.from: working` is chosen: the base is a temporary commit of the working tree on `refs/evolvekit/base-*`, and the engineer's working tree, index and HEAD are byte-for-byte unchanged (Task 1's `test_working_base_commits_a_snapshot_without_touching_the_tree`).
4. Windows: `git worktree add` under a path with spaces (every Task 1 test's repository is `my repo/app dir`, its run folder `run dir`), and worktree removal while a solver process still holds a file (Task 1's `test_remove_retries_on_windows_lock`: three tries, then the tree is kept and `False` is returned, never an exception).
5. The agent operator "improves" by editing the benchmark or the harness: the diff filter refuses anything outside `open`, and the brief forbids running the benchmark (Task 9's `test_agent_diff_outside_open_is_refused`, which reads the brief file too).

  - `tree_dir(run_dir: Path, candidate_id: str) -> Path` = `run_dir / "work" / "trees" / candidate_id`.

  - `resolve_commit(repo: Repo, ref: str) -> str` (40 hex; `TreeError` naming the ref).
  - `resolve_base(repo: Repo, ref: str) -> str` (`"working"` → `snapshot_working`, else `resolve_commit`).
  - `materialise(run_dir: Path, *, repo: Repo, base: str, diff: str, candidate_id: str) -> Tree`.
  - `remove(run_dir: Path, candidate_id: str) -> bool`; `remove_all(run_dir: Path, *, keep: Collection[str] = ()) -> list[str]` (ids removed).
  - `snapshot_working(repo: Repo) -> str`.
  - `normalise_diff(diff: str) -> str`; `changed_files(diff: str) -> list[str]` (toplevel-relative, sorted, both sides of a rename); `touches_only(diff: str, open: Sequence[str], *, prefix: str) -> list[str]`; `diff_between(repo: Repo, base: str, ref: str) -> str`; `diff_stat(diff: str) -> dict[str, Any]` (`{"added": int, "removed": int, "files": changed_files(diff)}` — toplevel-relative paths; a page shows a path's last part).
  - Constants: `GIT_FLAGS`, `AUTHOR = ("evolvekit", "evolvekit@localhost")`, `FIXED_DATE = "2000-01-01T00:00:00+0000"`, `REMOVE_TRIES = 3`, `REMOVE_WAIT_S = 1.0`.

```python
def test_remove_retries_on_windows_lock(repo, tmp_path, monkeypatch):
    run_dir, r = tmp_path / "run dir", tree.Repo(repo / "app dir")
    made = tree.materialise(run_dir, repo=r, base=head(repo), diff="", candidate_id="g001-c0001")
    calls, real = [], shutil.rmtree
    def flaky(path, *args, **kwargs):
        calls.append(path)
        if len(calls) < 3:
            raise PermissionError("The process cannot access the file because it is being used by another process")
        return real(path, *args, **kwargs)
    monkeypatch.setattr(tree.shutil, "rmtree", flaky)
    monkeypatch.setattr(tree.time, "sleep", lambda s: None)
    assert tree.remove(run_dir, "g001-c0001") is True
    assert len(calls) == 3 and not made.worktree.exists()
    assert "g001-c0001" not in git(repo, "worktree", "list"), "pruned from the repository's list"
    held = tree.materialise(run_dir, repo=r, base=head(repo), diff="", candidate_id="g001-c0002")
    def locked(*args, **kwargs):
        raise PermissionError("in use")
    monkeypatch.setattr(tree.shutil, "rmtree", locked)
    assert tree.remove(run_dir, "g001-c0002") is False and held.worktree.exists()
    assert tree.remove(run_dir, "never-made") is True

def test_normalise_diff_ignores_index_and_timestamps(repo):
    one = change(repo, {"app dir/solver.py": SOLVER.replace("VALUE = 5", "VALUE = 3")})
    norm = tree.normalise_diff(one)
    variants = [
        re.sub(r"^index .*$", "index 1234567..89abcde 100644", one, flags=re.M),
        one.replace("--- a/app dir/solver.py", "--- a/app dir/solver.py\t2026-11-07 10:00:00.000000000 +0100"),
        one.replace("+VALUE = 3", "+VALUE = 3   "),
        one.replace("\n", "\r\n"),
        change(repo, {"app dir/solver.py": SOLVER.replace("VALUE = 5", "VALUE  =  3")}),
        change(repo, {"app dir/solver.py": SOLVER.replace("VALUE = 5", "VALUE = 3")}, unified=6),
        change(repo, {"app dir/solver.py": SOLVER.replace("VALUE = 5", "# shorter tours\nVALUE = 3")}),
        change(repo, {"app dir/solver.py": SOLVER.replace("VALUE = 5", "\nVALUE = 3")}),
    ]
    assert all(tree.normalise_diff(v) == norm for v in variants)
    other = change(repo, {"app dir/solver.py": SOLVER.replace("VALUE = 5", "VALUE = 4")})
    elsewhere = change(repo, {"app dir/solver.py": SOLVER + "VALUE = 3\n"})
    assert tree.normalise_diff(other) != norm and tree.normalise_diff(elsewhere) != norm
    readme = change(repo, {"README.md": "top\n# shorter tours\n"})
    assert tree.normalise_diff(readme) != "", "a '#' line is a heading in Markdown, not a comment"
    assert tree.normalise_diff("") == ""

def test_touches_only_names_offenders_relative_to_prefix(repo):
```

`_git(cwd: Path, *args: str, identity: bool = False, env: Mapping[str, str] | None = None) -> str` runs `["git", *GIT_FLAGS, *args]` with `capture_output`, `encoding="utf-8"`, `errors="replace"`; with `identity` it adds `-c user.name=evolvekit -c user.email=evolvekit@localhost -c commit.gpgsign=false` and sets `GIT_AUTHOR_DATE` and `GIT_COMMITTER_DATE` to `FIXED_DATE`; a non-zero exit raises `TreeError` with the last stderr line; `FileNotFoundError` raises `TreeError("git is not installed: code studies need git on PATH (git-scm.com)")`. `GIT_FLAGS = ("-c", "core.autocrlf=false", "-c", "core.quotepath=false", "-c", "core.longpaths=true")`.

`Repo.__init__`: a missing folder raises `TreeError("<path>: no such folder")`; `git rev-parse --show-toplevel` and `--show-prefix` in that folder (the toplevel comes back with forward slashes: `Path(...).resolve()`).

The materialise sequence (the body the signature does not determine):

```python
def materialise(run_dir, *, repo, base, diff, candidate_id):
    worktree = tree_dir(run_dir, candidate_id)
    if worktree.exists():
        remove(run_dir, candidate_id)  # a crashed earlier attempt: the same id is the same commit again
    worktree.parent.mkdir(parents=True, exist_ok=True)
    _git(repo.toplevel, "worktree", "add", "--detach", "--quiet", str(worktree), base)
    made = Tree(worktree, worktree / repo.prefix if repo.prefix else worktree, base)
    if not diff.strip():
        return made
    patch = worktree.parent / f"{candidate_id}.patch"
    patch.write_text(diff if diff.endswith("\n") else diff + "\n", encoding="utf-8", newline="\n")
    try:
        _git(worktree, "apply", "--index", "--whitespace=nowarn", "--recount", str(patch))
```

The normalisation (design §11 leaves it to the builder; this is it):

```python
_HUNK = re.compile(r"^@@ -(\d+)(?:,\d+)? \+\d+(?:,\d+)? @@")
_DROP = ("diff --git ", "index ", "old mode ", "new mode ", "similarity index ", "dissimilarity index ", "\\ ")

def _side(path: str) -> str:            # "a/x" / "b/x" -> "x"; "/dev/null" stays
    path = path.split("\t")[0].strip().strip('"')
    return path[2:] if path[:2] in ("a/", "b/") else path

def _squeeze(text: str) -> str:         # indentation kept, inner runs of spaces collapsed, the end stripped
    lead = text[: len(text) - len(text.lstrip())]
    return lead + " ".join(text.split())

def _ignorable(text: str, path: str) -> bool:
    return not text.strip() or (path.endswith(".py") and text.lstrip().startswith("#"))

def normalise_diff(diff: str) -> str:
    out, group, anchor, old, minus, path = [], [], None, 0, "", ""
    def flush():
        nonlocal group, anchor
        if group:
            out.append(f"@ {anchor}"); out.extend(group)
        group, anchor = [], None
    for raw in diff.replace("\r\n", "\n").replace("\r", "\n").split("\n"):
        line = raw.rstrip()
        if line.startswith(_DROP):
            continue
        if line.startswith("--- "):
            flush(); minus = _side(line[4:]); continue
        if line.startswith("+++ "):
            plus = _side(line[4:]); path = minus if plus == "/dev/null" else plus
            out.append(f"F {path}"); continue
        hunk = _HUNK.match(line)
        if hunk:
            flush(); old = int(hunk.group(1)); continue
        if line[:1] in ("+", "-"):
            text = _squeeze(line[1:])
            if not _ignorable(text, path):
                anchor = old if anchor is None else anchor
                group.append(line[0] + text)
            old += line[0] == "-"
            continue
        if line.startswith(" ") or not line:
            flush(); old += 1; continue
        out.append(line)                 # binary patches, new/deleted/rename lines: as they are
    flush()
    return "\n".join(out) + ("\n" if out else "")
```

Two diffs against the same base with the same changes at the same base lines normalise alike, whatever their context width, `index` lines, timestamps, line endings, trailing or inner whitespace, blank lines, or (in `.py` files) full-line comments. A one-hunk `@@ -0,0` (a new file) anchors at 0.

`changed_files`: the `--- `/`+++ ` paths (`_side`), `/dev/null` dropped, a set sorted. `touches_only`: for each changed file, it is open when it starts with `prefix` and its remainder matches one glob of `open`; the glob is compiled by `**/` → `(?:.*/)?`, `**` → `.*`, `*` → `[^/]*`, `?` → `[^/]`, everything else `re.escape`d, anchored both ends. `diff_stat`: counts `+`/`-` lines inside hunks (not the `+++`/`---` headers); `files` = `changed_files`.

## Decisions

Choices made where the plan or the design was silent (the controller completes this after the builder check):

- **D1 — Cumulative diffs.** A candidate's `block` is always the diff against the base, never against its parent; operators that work on the parent's tree read the child's block back with `git diff --cached <base>` (`tree.staged_diff`).
- **D2 — Deterministic candidate commits.** Candidate commits use the author and committer `evolvekit <evolvekit@localhost>` at `2000-01-01T00:00:00+0000` with the message `evolvekit candidate <id>`, so the same change is the same commit across sessions and run folders. They skip the engineer's hooks and signing (`--no-verify`, `-c commit.gpgsign=false`): they are internal and never pushed. The empty diff is no commit (`Tree.commit == base`).
- **D3 — `doctor`'s git line never fails.** Missing git is `ok: true` with "not found: only code studies need it", so `doctor` keeps exit 0 on a settings-only machine.
- **D4 — Normalisation.** Context lines, hunk line counts, `index`/mode lines, timestamps, CR, trailing and inner whitespace runs, blank added or removed lines, and full-line `#` comments in `.py` files are ignored; indentation and the base line of each change group are kept. Comments in other languages, and `#` lines in Markdown, count.
- **D5 — Removal.** `tree.remove` deletes the folder (three tries, 1 s apart) and then runs `git worktree prune`, instead of `git worktree remove`, so a lock can be retried and reported, never forced.
- **D6 — Code and tuned settings together are refused for now.** Design §5.2 allows both; this plan refuses a study that varies code and tunes settings together, with a sentence, and keeps fixed settings working. Joining a diff and a configuration in one candidate is left for later (open question).
- **D7 — `templates/faster.yaml` and its test move to Task 7.** `load_harness` compiles every template as a study, so the template cannot exist before `vary.code` parses.
- **D8 — The compile inserts `builtin-build` in Task 7**, second after `builtin-static` (the config requires the static stage first). Task 3 adds the stage kind and its config rules.
- **D9 — Serial evaluation with `build`.** The driver runs the cascade once per candidate. To keep that true to the plan's numbers, a code study with a build gets no screening stage.
- **D10 — The program of a program-harness code study.** `study code` also sets `application.path` to the program inside the engineer's checkout (`code.app` resolved against `vary.code.repo`) when it is empty, so the preview and the plan's timing work. The search always runs the program from each candidate's tree.
- **D11 — The harness's origin.** `library.create_study` records the harness folder in `<study>/harness-origin.txt`. Set up and `study code` without `--repo` propose the harness's `code.repo` resolved against it while that folder still has the harness.
- **D12 — The bake-off's top-level verdict.** The bake-off's top-level verdict is that of the "chosen" candidate. That is the largest mean among those deciding `use`, else the largest mean. `candidates` lists every ref in the order given, and the key exists only on bake-off runs (`SCHEMA` stays 1). Refs that change files outside `open` are refused up front.
- **D13 — No-search operators.** A bake-off, or a code study without AI, compiles to `search.operators: {param_lhs: 1.0}` with zero rounds. That keeps the config loadable without models, and the operator is never invoked.
- **D14 — `agent_patch` details.** It uses the `strong` model role. Its brief is written to `<run>/work/briefs/` (outside the tree, so never in the diff) and passed whole to `act`. Claude gets it on stdin, Copilot on the command line. An agent stopped at the turn limit keeps its edits. The time limit is `models.<role>.options.act_timeout_s`, 1800 s by default.
- **D15 — The PR commit.** The PR's commit is a fresh commit on the base with the best's tree, made with the engineer's own git identity, hooks and signing, and never the evolvekit candidate commit. Its message is the study's title and the verdict's line. `gh` is used only when the remote URL is on GitHub; otherwise the command says where the branch is. When `--base` is not given, the PR goes into the repository's default branch.
- **D16 — Test subjects.** Task 2's driver tests script the operator (`run_operator` patched) instead of the fake provider, because the diff prompts land in Task 5. The bake-off's slow test uses a temporary repository copied from `examples/cli-solver`, so it can make branches without touching the evolvekit checkout. Task 4's and Task 6's demo-tour tests use the evolvekit checkout at `HEAD`, as design §5.7 says.
- **D17 — File names.** The plan's file map had `evolvekit/operators/*`. The code puts operators in `evolvekit/search/operators.py`, so the diff prompt lives in `evolvekit/tree_prompts.py` and the agent operator in `evolvekit/search/agent_patch.py`.
- **D18 — demo-tour becomes 1.1.0.** An installed 1.0.0 copy would otherwise win over the built-in harness and hide `code:`. `tests/test_harness_cli.py` follows.
- **D19 — A code study's AI requirement.** It is a `study_problems` sentence (key `budget.ai`) when `for_search` is on. The bake-off and the template check pass `for_search=False`.
- **D20 — `study export` takes `--diff` only.** Without it, the command exits 2 and names the flag.
- **D21 — Where trees go and when they leave.** Search trees live in `<run>/work/trees/`, the final check's in `<run>/confirm/<label>/work/trees/`, and drafts are `<id>.draft`. A draft is removed by its operator; the final check's trees go when it ends; the search's trees go at the end of each round (the rejected and the raced out) and at the end of the run (all but the best's). A study that is deleted while its trees exist leaves entries that `git worktree prune` clears. Superseded by the final review: every tree goes when its evaluation ends.
- **D22 — Git version.** The README asks for git 2.30 or later. The code relies on `worktree add --detach`, `apply --recount` and `rev-parse --show-prefix`, all much older. The tests use `init -b` (2.28 or later).
- **D23 — Execution order.** The order is the bake-off first (Tasks 1, 2, 3, 4, 6, 7, 8), then mutation (Tasks 5, 9), then 10–13. Task 7 compiles code studies with `diff`/`rewrite` operators before Task 5 teaches those operators trees. A code-study search started between those two tasks would fail; the bake-off would not.
Taken by the controller on the planner's open questions (before the builder check):

24. **Code and settings in one study.** §5.2 says a study may vary code alone or together with settings, but nothing in the design says how one candidate carries both a diff and settings. This project ships code alone; `study check` refuses the mix with "this version varies code or settings in one study, not both; a later project combines them". This is a recorded deviation from §5.2 for the owner. Cost if wrong: an engineer who wants both must run two studies.
25. **"One combination at a time" is a note, not a warning.** §5.1 says `harness check` "says so in a warning", but a warning makes the check exit 1 and the harness skill's loop ("until exit 0") could never end for a harness with a build. The check prints the sentence as an informational note (exit unchanged). Cost if wrong: a reader skimming only ✗ lines misses it.
26. **A bake-off branch may touch files outside `open`.** The engineer wrote the branch; the bake-off compares it as it is, prints a note naming the files outside `open`, and goes on. The static stage's refusal (§5.1) applies to generated candidates (the mutation operators), where it protects the benchmark. Cost if wrong: a branch that edits the benchmark itself is compared as if fair; the note says so.
27. **Candidate commits** are made in detached worktrees under the run folder with a fixed author and `--no-verify`; the engineer's branches, hooks and identity are untouched until `study pr`, which uses their own. Accepted.
28. **A bake-off's headline claims no winner.** The verdict's `line` for a bake-off says how many branches were compared and that each has its own verdict; `decision` at the top level is `none` for a bake-off and each candidate carries its own decision and line. No multiple-comparison correction: the rule stays the fixed rule per candidate against the base, and the document never names "the best branch". Cost if wrong: an engineer reading only the candidates' `use` lines may over-trust the best of many; the report's "How it ran" says how many were compared.
29. **`study pr` does not refuse on a non-`use` verdict.** §5.6 asks for the branch from the best candidate's commit and the report as the body; the report's verdict says keep or worse when it does, `study pr` prints the verdict's line first and needs `--yes`. Cost if wrong: a PR whose body says "keep today's" exists; the engineer asked for it.
30. **The plan's length** (about ten times §5) is mostly test code; the builder check judges whether any task reads as a transcript rather than a plan, and the controller trims only what it names.

Taken by the controller after the builder check (they supersede 24, 26 and 28 where they say so):

31. **The shared interpreter is put back.** For a harness with `build` (a `python` harness: `pip install -e {tree}` into the study's application Python), every place that builds a candidate — the search, the final check, `harness check` — runs `build` once more in a `finally` with `{tree}` = the folder `vary.code.repo` names (the engineer's own checkout), so the interpreter never points at a removed worktree; a failure there is a warning in the run's log and in the check's output. The build cache is in memory, keyed by commit, for one process only; nothing on disk claims a build (no `last-build.json`).
32. **A bake-off chooses, but never says "the best branch".** (Supersedes 28.) `job.final.candidate` is the candidate with the largest `mean_pct` among those whose own decision is `use` (so `study pr` and `_changed` work as in Task 8); the top-level `decision` and `line` are that candidate's, with the line prefixed "Of N branches, `<ref>`: "; when no candidate is `use`, the top-level decision is `keep` and the line "None of the N branches is shown to beat the starting point." (the existing `none` keeps its meaning). The report's "How it ran" says "N branches were compared; the more are compared, the likelier one looks ahead by chance." Every candidate's own line stays in `candidates`.
33. **A bake-off branch that touches files outside `open` is refused**, with a sentence naming the files and how to include them (the harness's `code.open`, or `vary.code.open`). (Supersedes 26; D12 and Task 8 hold.)
34. **The bake-off diff is the branch's own change:** `git diff base...ref` (from the merge-base), not `base..ref`, so a branch cut from an older base is not measured as reverting the base's newer commits; a diff that then does not apply on the base refuses the candidate with "does not apply on the base; rebase `<ref>` onto it". A recorded deviation from §5.5's wording, for the owner.
35. **`study pr` after `from: working`:** the branch is made from the repository's `HEAD` with the best candidate's diff applied (the engineer's uncommitted work is not in the diff); a diff that does not apply on `HEAD` refuses with the path of `study export --diff`'s patch.
36. **Time bounds.** An `act` call's timeout is the smaller of `act_timeout_s` and the study's time left; a build's likewise with `build_timeout_s`; a Stop request ends a running `act` or build by killing its process tree (as the gate script does). A per-call spending cap is passed to the tool when the installed CLI offers one (verify against its `--help`; record the flag), else the budget is checked after each call as today.
37. **Operators on a tree.** For tree problems the compile emits the diff operator (and `agent_patch` when the provider supports `act`); `rewrite`, `crossover` and `big_step` are not emitted for trees in this project. With marked blocks in an open file, the existing block rewrite applies to the block and its result becomes the diff.
38. **The words of 24 and 25.** The refusal sentence for code with settings is the one Task 7 and D6 quote (24's own wording is withdrawn). "One combination at a time" is a passing check line whose message is that sentence (no new severity in the `--json` contract); Task 6's test asserts a pass with that message.
39. **The brief is a file for both providers.** The agent receives a short prompt naming the brief file (`work/briefs/<candidate>.md`) and the rule "read it first"; the brief itself never goes on the command line (Windows' limit).
40. **How to read the long steps.** Where a step carries a full body (Task 1 Step 4, Task 8 Steps 3–5, Task 9 Steps 3–4, Task 10 Step 3, Task 12 Step 3), the tests are the contract and the body is a sketch the implementer may replace.
