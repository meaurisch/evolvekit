# Agent path, project 3: Code studies — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Before executing:** this plan is at task level. Re-read the engine (`evolvekit/search/driver.py`, `evolvekit/candidate.py`, `evolvekit/evaluate/stages.py`, `evolvekit/harness/compile.py`) as it is after project 2 landed, expand every task to step level with superpowers:writing-plans (keep the tasks, files, interfaces and test names below), and run the builder check on the result. The milestones are in order: the bake-off (Tasks 1–4, 6–8) ships before any mutation (Tasks 5, 9).

**Goal:** a study may change a source tree: a candidate is a commit, the harness builds and benchmarks it, given branches can be compared with the verdict, a coding agent can be the mutation operator, and the result is a PR.

**Architecture:** the engine gains `problem.tree` beside `problem.skeleton`: a candidate's `block` is a unified diff against a base commit, materialised as a detached git worktree with a commit per candidate, built by a new `builtin-build` stage, and run by the command stages with `{candidate}` as the tree path. The harness declares `code:`; the study declares `vary.code`; the compile maps one to the other. A provider may `act` in a tree; the `agent_patch` operator turns the agent's edits into a diff. The bake-off is a run with zero rounds whose candidates are given refs.

**Tech stack:** Python ≥ 3.11 standard library, `git` on `PATH` (the first new external requirement, checked by `doctor`), the existing providers.

**Spec:** [docs/superpowers/specs/2026-11-07-agent-path-design.md](../specs/2026-11-07-agent-path-design.md), §2 and §5.

## Global constraints

- One harness per application; `code:` is a section of it (spec §5.1).
- A candidate that touches a file outside `open` is refused at the static stage (spec §5.1, §5.4).
- Nothing is pushed and no PR is opened without `--yes` (spec §5.6).
- The verdict is the only claim; the PR body is `study report --markdown` (spec §2, §5.6).
- PyVRP is not a test subject (spec §5.7).
- `git` is required for code studies only; settings studies must still work without it.
- Branch `agent/3-code` from `agent/2-skills`; PR against `master`, stacked; merge commit.

## Review focus

1. A diff that applies but leaves the tree unbuildable or the tests failing: `builtin-build` hard-rejects with the stderr tail as feedback, and the tree is removed (Task 3's `test_build_failure_is_a_hard_reject_with_feedback`).
2. Two candidates whose diffs differ only in whitespace or in a comment: the normalised diff makes them duplicates (Task 1's `test_normalise_diff_ignores_index_and_timestamps`; Task 2's `test_whitespace_only_diffs_are_duplicates`).
3. The repo has uncommitted changes when `vary.code.from: working` is chosen: the base is a temporary commit of the working tree, and the engineer's working tree is never touched (Task 1's `test_working_base_commits_a_snapshot_without_touching_the_tree`).
4. Windows: `git worktree add` under a path with spaces, and worktree removal while a solver process still holds a file (Task 1's `test_remove_retries_on_windows_lock`).
5. The agent operator "improves" by editing the benchmark or the harness: the diff filter refuses anything outside `open`, and the brief forbids running the benchmark (Task 9's `test_agent_diff_outside_open_is_refused`).

### Task 1: `tree.py`

**Produces:** `Repo(path) -> Repo` with `toplevel: Path` and `prefix: str` (`git rev-parse --show-toplevel` / `--show-prefix` of the folder `repo` names; an error when it is not inside a git repository); `materialise(run_dir: Path, *, repo: Repo, base: str, diff: str, candidate_id: str) -> Tree` (`Tree(worktree, path, commit)` where `path = worktree / prefix` is `{tree}`; `git worktree add --detach` of the whole repository, `git apply --index --whitespace=nowarn` with paths relative to the toplevel, `git commit` with a fixed author); `remove(run_dir, candidate_id)` (retries three times over 2 s on `PermissionError`, Windows); `snapshot_working(repo) -> str` (a temporary commit of the working tree on a detached ref `refs/evolvekit/base-<time>`, the tree itself untouched); `normalise_diff(diff: str) -> str` (drops `index` lines, timestamps and trailing whitespace; keeps hunks); `touches_only(diff: str, open: list[str], *, prefix: str) -> list[str]` (the files outside `open`, with `open` globs relative to the prefix; empty when fine); `diff_between(repo, base, ref) -> str`.

**Tests:** `test_repo_toplevel_and_prefix`, `test_repo_outside_git_is_an_error`, `test_materialise_applies_and_commits`, `test_materialise_empty_diff_is_the_base`, `test_tree_path_is_prefix_inside_worktree`, `test_remove_retries_on_windows_lock`, `test_working_base_commits_a_snapshot_without_touching_the_tree`, `test_normalise_diff_ignores_index_and_timestamps`, `test_touches_only_names_offenders_relative_to_prefix`, `test_diff_between_refs`. All on a temporary git repository made by the test, with the folder of interest in a subfolder.

### Task 2: The driver on trees

**Produces:** `problem.tree: {repo, base, open, build, build_timeout_s, app}` in `config.py` (mutually exclusive with `skeleton`; `repo` absolute; `base` resolved to a commit at load; `working` → `snapshot_working`); `Candidate.commit`; the seed candidate's `block` is `""`; `Driver._make_source` returns the tree path for tree problems; dedup and the structural novelty filter use `normalise_diff`; trees of rejected and raced-out candidates removed at generation end, all but the best's at run end; `runs.jsonl` rows carry `commit`; **when `build` is set, the driver evaluates one candidate at a time** (the fan-out of a generation is sequential; `workers` still parallelise one candidate's instances), spec §5.3.

**Tests:** `test_seed_is_empty_diff_at_base`, `test_whitespace_only_diffs_are_duplicates`, `test_trees_are_removed_except_best`, `test_runs_rows_carry_commit`, `test_build_serialises_candidates` (a build command that records overlapping start/end times fails the test when two overlap), `test_no_build_keeps_concurrency`, with the fake provider returning diffs from a fixture list.

### Task 3: `builtin-build`

**Produces:** a stage kind `builtin-build` that runs `problem.tree.build` (substitutions `{tree}`, `{python}`) in the tree with `build_timeout_s`; failure is a hard reject with `failure: build` and the stderr tail as feedback; success caches by commit so a resumed run does not rebuild. The compile inserts it first when `build` is set.

**Tests:** `test_build_runs_in_the_tree`, `test_build_failure_is_a_hard_reject_with_feedback`, `test_build_timeout`, `test_build_cached_by_commit`.

### Task 4: Command stages on trees

**Produces:** `{candidate}` substitutes the tree path; a new `{app}` substitutes `problem.tree.app` rendered with `{tree}`; `compile.command()` for a program harness with `code:` uses `{app}`; for a python harness the application Python is the study's, into which `build` installed the tree.

**Tests:** `test_argv_substitutes_tree_and_app`, `test_demo_tour_code_candidate_runs_from_its_tree` (a diff that changes `solver.py`'s banner; the stage's stdout shows the change).

### Task 5: Diff-prompt operators
